# Two-Agent Workflow — Claude plans, Codex executes

Claude is the senior: decides what to do, writes the brief, reviews the outcome.
Codex is the worker: executes inside a fixed scope and reports back.

The design constraint is that **Claude never reads the diff.** It reads a report whose
facts are generated by a script, not written by the model that did the work.

> **Status.** This document is the spec. None of the tooling it describes exists yet —
> `AGENTS.md`, `Makefile`, `scripts/slice_report.sh`, `.importlinter`, `tasks/`, and
> `.claude/commands/` all still need creating. Templates below are complete enough to
> copy verbatim.

## 1. Shared knowledge

Both agents read the same files. One source of truth, no drift.

```
repo/
  AGENTS.md              <- canonical agent instructions (currently docs/CLAUDE.md)
  CLAUDE.md -> AGENTS.md <- symlink
  docs/
    architecture.md  refactor-plan.md  PHASE-2-REVIEW.md
    TEST-STRATEGY.md  backlog.md  liveness-audit.md  adr/
  tasks/                 <- the handoff surface
  ci/gate.py             <- the ratchet gate (exists)
  scripts/slice_report.sh
  Makefile
```

```bash
git mv docs/CLAUDE.md AGENTS.md
ln -s AGENTS.md CLAUDE.md
git add AGENTS.md CLAUDE.md
```

Claude Code auto-loads `CLAUDE.md`; Codex auto-loads `AGENTS.md`. **Verify the latter
against your Codex version with a throwaway task before relying on it** — if it doesn't,
have every brief name the file explicitly in its "Read first" section.

(`refactor/` — which duplicated four `docs/` files — has been deleted and its links
repointed. Nothing further to do there.)

### The gate is `ci/gate.py`, not raw commands

You already have a ratchet gate. Both agents must invoke *it*, not re-derive the checks,
or the two will disagree about what "green" means.

```makefile
.PHONY: gate gate-update test types lint imports
gate:        ; python ci/gate.py
gate-update: ; python ci/gate.py --update
test:        ; .venv/bin/python -m pytest -q
types:       ; pyright --outputjson | jq '.summary'
lint:        ; .venv/bin/ruff check .
imports:     ; lint-imports
```

The ratchet has a consequence for the workflow: a slice that *improves* a number must
lower the baseline **in the same commit**. `gate.py` prints the slack under "Slack to
bank." That's a required report field, not a nicety — unbanked slack silently widens the
tolerance for every later slice.

## 2. The brief — Claude writes, Codex reads

One file per slice: `tasks/slice-06a.md`. Fixed schema. The allowlist is the important
part: it turns scope from an instruction into something a script can check.

```markdown
# slice-06a — Extract run lifecycle into services/

## Objective
Move batch-run orchestration helpers out of fastapi_run.py into
app/services/runs/lifecycle.py. Behavior must not change.

## Read first
- AGENTS.md
- docs/refactor-plan.md § "Slice 6 — Extract services"
- docs/PHASE-2-REVIEW.md § R8
- docs/TEST-STRATEGY.md § 4

## Allowlist
Only these paths may change. Anything else is a scope violation.
```allowlist
app/fastapi_run.py
app/services/__init__.py
app/services/runs/__init__.py
app/services/runs/lifecycle.py
ci/baseline.json
```

## Symbols to move
_run_prefect_batch (L1185), _run_prefect_inprocess_batch (L1367),
_compute_cutoff_iso, _slugify, _build_seeds_from_focus, _build_seeds_from_urls,
_TemporaryEnv, _filter_listings_by_cutoff, _augment_with_potential_applications

## Shim strategy
None required — all private, zero external importers. Verify per symbol with LSP
findReferences before moving. If any has an importer outside fastapi_run.py, STOP.

## Forbidden
- Do NOT deduplicate the two batch runners. Move only.
- Do NOT edit anything under tests/. Not one line, not one new file.
- Do NOT fix unrelated issues you notice — list them in the report instead.
- Do NOT add dependencies.
- Do NOT raise a number in ci/baseline.json. Lowering is required when you improve one.

## Stop and ask
- Any symbol has an importer outside fastapi_run.py
- The move would create an import cycle
- A contract test fails and the fix is not obviously in the moved code

## Gate
make gate

## Slice-specific check
python -c "
import sys
for m in list(sys.modules):
    if m.startswith(('fastapi','starlette')): del sys.modules[m]
import app.services.runs.lifecycle
assert not any(m.startswith('fastapi') for m in sys.modules)
print('services layer is HTTP-free')"

## When done
./scripts/slice_report.sh slice-06a
Then fill in the NARRATIVE section only. The FACTS section is generated — do not edit it.
```

## 3. The report — script generates facts, Codex adds narrative

`scripts/slice_report.sh`:

```bash
#!/usr/bin/env bash
# usage: ./scripts/slice_report.sh <slice-id> [base-ref]
set -uo pipefail
SLICE="${1:?usage: slice_report.sh <slice-id> [base-ref]}"
BASE="${2:-main}"
TASK="tasks/${SLICE}.md"
OUT="tasks/${SLICE}.report.md"
[ -f "$TASK" ] || { echo "missing $TASK"; exit 1; }

ALLOW=$(awk '/^```allowlist$/{f=1;next} /^```$/{f=0} f' "$TASK" | sed '/^$/d')
CHANGED=$(git diff --name-only "$BASE"...HEAD)

{
  echo "# ${SLICE} — report"
  echo
  echo "<!-- FACTS: generated by scripts/slice_report.sh. Do not edit. -->"
  echo "## FACTS"
  echo
  echo "Base \`$BASE\` · Head \`$(git rev-parse --short HEAD)\` · $(date -u +%FT%TZ)"
  echo
  echo '### Ratchet gate'
  echo '```'
  python ci/gate.py 2>&1 | tail -25
  echo '```'
  echo
  echo '### Baseline delta'
  echo '```'
  git diff "$BASE"...HEAD -- ci/baseline.json | grep -E '^[+-] *"' || echo '(baseline unchanged)'
  echo '```'
  echo
  echo '### Diffstat'
  echo '```'
  git diff --stat "$BASE"...HEAD | tail -30
  echo '```'
  echo
  echo '### Scope check'
  VIOL=0
  while read -r f; do
    [ -z "$f" ] && continue
    grep -Fxq "$f" <<<"$ALLOW" || { echo "- OUT OF SCOPE: \`$f\`"; VIOL=1; }
  done <<<"$CHANGED"
  [ "$VIOL" -eq 0 ] && echo "- all changed files are within the allowlist"
  echo
  echo '### tests/ untouched'
  if git diff --name-only "$BASE"...HEAD -- tests/ | grep -q .; then
    echo '- **VIOLATION** tests/ was modified:'
    git diff --name-only "$BASE"...HEAD -- tests/ | sed 's/^/  - /'
  else
    echo '- confirmed: no changes under tests/'
  fi
  echo
  echo '### Module size'
  echo '```'
  wc -l app/fastapi_run.py 2>/dev/null
  echo '```'
  echo
  echo "<!-- NARRATIVE: filled in by the executing agent. -->"
  cat <<'EOF'
## NARRATIVE

### Decisions taken that were not in the brief

### Stop-and-ask conditions hit

### Slack banked or left on the table
(if gate.py reported slack and the baseline was not lowered, say why)

### Problems noticed but NOT fixed (per Forbidden)

### Left undone
EOF
} > "$OUT"
echo "wrote $OUT"
```

Gate output, baseline delta, diffstat, scope violations, and the `tests/` check are all
computed from git and `ci/gate.py`. They cannot be misreported. Codex writes only the
five narrative fields — the parts that need a mind, and the only parts Claude reads.

## 4. Claude Code slash commands

These are the Phase 3 project skills, and they are more useful than the generic ones.

`.claude/commands/slice-brief.md`:

```markdown
---
description: Generate a Codex task brief for a slice
---
Read docs/refactor-plan.md, docs/PHASE-2-REVIEW.md and AGENTS.md. For slice
$ARGUMENTS, write tasks/$ARGUMENTS.md following the schema in
docs/AGENT-WORKFLOW.md §2.

The allowlist must be exhaustive and minimal. Derive stop-and-ask conditions from
that slice's entries in the plan's risk register. Do not write application code.
```

`.claude/commands/slice-review.md`:

```markdown
---
description: Review a completed slice from its report
---
Read tasks/$ARGUMENTS.report.md only. Do not read the diff unless the report
gives you cause.

Return one of:
- ACCEPT — gate passed, scope clean, slack banked, narrative raises nothing
- FIX — append a "## Followup" section to tasks/$ARGUMENTS.md with precise
  instructions, and say what to re-run
- ESCALATE — a decision is needed that the brief did not cover; state it and stop

Request a specific hunk only on a scope violation, an unexplained diffstat, a
raised baseline number, or a decision that changes behavior.
```

## 5. The loop

```
Claude Code   /slice-brief slice-06a   -> tasks/slice-06a.md
Codex         reads AGENTS.md + brief, works on branch slice/06a
              runs ./scripts/slice_report.sh slice-06a, fills NARRATIVE
Claude Code   /slice-review slice-06a  -> ACCEPT | FIX | ESCALATE
```

One branch per slice, so Claude can request a hunk by commit without loading the diff.

**Token cost to Claude per slice:** the report is ~100 lines, roughly 1.5k tokens, versus
30–50k for a full structural diff.

## 6. Where Claude should still read code

Three exceptions. Everything else stays behind the report.

1. **The Slice 1 contract test suite.** It is the oracle every later gate is graded
   against. If it is wrong, every green gate afterward is meaningless. Read it once,
   properly.
2. **Any ESCALATE.** By definition the report was insufficient.
3. **Gate passed, outcome wrong.** The gate has a hole. Read the code, then close the
   hole with a new executable check so it never needs reading again.

## 7. Make architecture executable

Every rule encoded as a command is a rule Claude never reviews by eye. This is what keeps
the arrangement cheap as slices accumulate, so invest here first.

```bash
pip install import-linter    # add to requirements.lock.txt
```

`.importlinter`:

```ini
[importlinter]
root_package = app

[importlinter:contract:layers]
name = Layered architecture
type = layers
layers =
    app.api
    app.services
    app.pipeline
    app.sources
    app.fetching
    app.db
    app.config
    app.common

[importlinter:contract:no-api-imports]
name = Nothing imports app.api
type = forbidden
source_modules =
    app.services
    app.pipeline
    app.db
forbidden_modules =
    app.api

[importlinter:contract:pipeline-source-agnostic]
name = pipeline does not import a concrete source
type = forbidden
source_modules = app.pipeline
forbidden_modules = app.sources.stepstone
```

Contracts referencing packages that do not exist yet (`app.services`, `app.sources`) will
fail until the slice that creates them lands — that is correct, and it makes the layering
a target the gate enforces rather than a paragraph in a document.

Wire `lint-imports` into `ci/gate.py` as a fourth measurer with its own ratchet count, so
violations appear in the FACTS section automatically and need no human judgment.
